# Codex 接入

简体中文 · [English](CODEX-INTEGRATION.en.md) · [返回 README](../README.md)

首次安装请先阅读 [macOS 从零安装步骤](../README.md#安装与构建)，完成 Homebrew/Codex CLI 安装及 MyTerm 首次打开。

本页描述 MyTerm 的接入实现；版本变更见 [历史更新日志](../CHANGELOG.md)。SSH 分析启动时默认勾选“允许执行 SSH 命令”，确认启动后生效；实际命令按执行配置中的审批模式处理，可取消勾选保持只读。

接入窗口使用左侧纵向导航：**Codex 配置**包含可执行文件、代理、登录与外部 MCP；**SSH 会话接入**用于启动 SSH 分析；**本地工作**用于选择目录并直接启动本地 Codex。窗口可调整大小，右侧内容可滚动。

| 用途 | 本地工作 | SSH 会话接入 |
| --- | --- | --- |
| 启动前选择 | 工作目录，默认用户主目录 | 已打开的 SSH 会话 |
| MyTerm MCP | 本次启动禁用，无需注册 | 自动配置并读取所选会话 |
| 命令执行和审批 | Codex 原生工具、workspace-write / on-request | MyTerm 独立 SSH 通道及会话授权 |
| 命令容量与超时 | 由 Codex 自身管理 | 默认 4096 字节、60 秒、1 MiB 输出，均可配置 |
| Codex 网络代理 | 复用 Codex 配置 | 复用同一配置，与 SSH 代理独立 |

## SSH 分析启动

1. 打开 SSH 标签，再打开 **MyTerm → Codex 接入…**。
2. 在 **Codex 配置** 中填写 CLI 路径（默认 `/opt/homebrew/bin/codex`，已有自定义路径保留），配置独立的 HTTP / SOCKS5 代理（可选代理认证）。登录检查、代理测试、外部 MCP 注册各自显示状态。
3. 点击登录或直接启动。MyTerm 会检查本地登录凭据；需要登录时先完成设备码登录，再继续先前选择的任务。主动重新登录用于更换账号或处理失效凭据。
4. 在 **SSH 会话接入 → 启动 Codex 标签** 选择一个已打开的 SSH 会话，以及可选的历史回溯、执行权限；开启“接入时读取已有输出”后可调整历史读取范围。确认成功后关闭接入窗口；取消不启动标签。
5. 在 Codex 标签中输入排查目标。启动提示已包含所选会话 ID，不需要再次选会话。

CLI 路径或代理格式无效时禁止启动，并提供返回配置入口。登录检查只确认本地凭据，不验证服务端是否撤销；代理测试只验证 HTTPS 链路，不代表模型请求可用，也不是启动的强制前提。修改配置只影响新建标签；修改 CLI 路径使登录检查结果失效，修改连接配置使代理测试结果失效。

登录、检查与内置标签使用 `cli_auth_credentials_store="file"`，沿用 Codex 凭据位置（默认 `~/.codex/auth.json`），不改写全局配置。登录不授予 SSH 访问权限。Codex 标签结束后保留输出、退出码及可识别错误的处理建议。

## 本地 Codex

在 **MyTerm → Codex 接入 → 本地工作** 确认或选择工作目录，点击 **启动本地 Codex** 即可。默认目录为用户主目录；无需先打开 Bash 或 SSH 标签，也不关联、读取其他标签的输出。

复用 **Codex 配置** 中的登录及 HTTP/SOCKS5 代理，不修改 `~/.profile`、普通 Bash 或 SSH 的代理。本地模式不启用 MyTerm MCP，不依赖外部 MCP 注册或终端共享。登录完成后自动继续启动，成功后关闭接入窗口。

本地命令与文件操作由 Codex 自身执行，使用 `workspace-write` 沙盒和 `on-request` 审批：所选工作目录允许写入，并非每条命令都需 MyTerm 确认。它不会继承其他 Bash 标签中的临时变量、别名或运行中的程序。SSH 分析仍通过“SSH 会话接入”选择目标并使用原有授权流程。


## SSH 共享与会话 ID

启动选择框确认后自动开启接入并授权所选 SSH 标签，无需额外开启总开关；本地 Shell 不参与共享，未选择的 SSH 标签不会自动授权。每次启动 MyTerm 均需重新选择会话。

关闭接入设置窗口不停止共享。关闭最后一个关联的 Codex 标签、关闭对应 SSH 标签或退出 MyTerm 会撤销相应访问；其他 Codex 标签仍关联同一 SSH 会话时保留读取权限；已发送给 Codex 的数据无法撤回。

内置 SSH 分析标签自动接收所选 SSH 标签的会话 ID，无需手工复制。外部 Codex 用 `list_sessions` 查询已授权会话。会话 ID 是运行中标签的 UUID，不是服务器配置 ID；同一服务器的不同标签具有不同 ID，关闭后新建会话会改变。

## SSH 历史与输出读取

SSH 分析标签默认不会在启动时主动读取已有 SSH 输出。需要先分析历史时，在选择 SSH 会话的窗口勾选“接入时读取已有输出”；否则等待你的任务，从后续命令开始分析。应用仅在本地建立输出游标基线，不把初始快照发送给 Codex。此选项控制启动流程，不是历史访问权限隔离；之后仍可明确要求回溯历史。游标失效或终端快照截断须提示覆盖缺口；通过执行接口运行的命令仍须读取全部 `command_status` 分页，直到 `all_output_delivered=true`。

历史选择支持 500 / 1000 / 2000 / 5000 / 10000 行及 64 KiB / 256 KiB / 1 MiB，默认 2000 行、256 KiB。行数和容量任一达到上限即截断。`capture_history` 冻结快照，随后通过 `read_history_page` 读完每一页，直到 `next_cursor=null`，避免刷屏期间分页漏行。每页最多 4000 字节，最多保留四份各 1 MiB 的快照，撤销共享时清除。

读取不要求开启磁盘日志，也不改变终端尺寸、光标或传输数据。只能访问 MyTerm 现有缓冲区、选区及全屏程序当前画面，不能恢复被移除的历史或远端未显示的文件内容；仍受模型上下文和额度限制。

已移除持续监控。Codex 按任务需要读取输出，并在获准执行命令后取回完整结果；不会通过后台循环持续采样空闲终端。新客户端不再发现 `watch_output`；旧客户端调用时立即返回 `stopped=true`，不读取终端数据，也不等待变化。

## SSH 命令执行与计划

执行授权、命令审批与取消操作集中在对应的 Codex 标签中，不再从接入设置打开独立的执行记录窗口。

移除后台监控**不影响自主多步排查**。你给出任务并授权执行后，Codex 仍可运行命令、读完全部输出，再选择下一步检查；逐条批准与“本会话始终允许”均保留。明确要求定时检查时，可约定间隔及持续时长/次数，并在授权范围内执行。这与没有任务时自动采样空闲终端不同。

启动时默认勾选“允许执行 SSH 命令”，确认启动后生效，实际命令按配置的审批模式执行；取消勾选可保持只读。可设置授权时长（1–1440 分钟）和额度（1–10000 条），默认 60 分钟、300 条；到期或额度用尽可在原标签继续授权，无需重新打开 Codex 标签。

- 计划仅由 Codex 在终端中展示，MyTerm 不捕获或重复展示。可以要求 Codex 修改或停止计划；逐条审批模式下也可拒绝待执行命令。选择始终允许后可取消当前命令，或关闭 Codex 标签以结束授权。
- 默认逐条审批：显示目标、完整命令和理由，点击“单次允许”才执行；也可点击“始终允许”或切换为“本会话始终允许”。不使用 Y/y 快捷确认。
- 模式可随时切换。切回逐条确认影响后续提交，不撤销已批准的排队命令或正在执行的命令；需要中断时点击“取消当前命令”。
- 实际执行授权仅属于当前 Codex 标签，不保存到磁盘；断线、到期或关闭标签后失效。默认审批模式可保存，运行中的选择仅影响当前标签。继续授权沿用该标签的限制与审批模式，重置额度，并取消旧待执行或运行中的命令。
- 同一个 SSH 标签可以关联多个 Codex 标签。每个 Codex 标签的授权时长、命令额度、审批模式、执行记录和输出读取进度独立；启动、续期、停止或关闭其中一个，不会替换其他标签的授权。已批准的命令按提交顺序串行使用同一 SSH 执行通道；`queued` 表示已批准、正在等待，无需重复提交或重新授权。关闭 SSH 标签或连接断开会使所有关联执行授权失效。外部 MCP 默认仅能读取已共享会话，不能借用内置 Codex 标签的执行授权。

MCP 结果中的 `execution_authorization` 报告当前界面选择的模式。选择始终允许后，提交命令直接返回运行中任务是正常行为；只有 `awaiting_approval` 需要点击批准。旧对话若仍坚持默认逐条审批，可告诉 Codex：“我已在 MyTerm 选择本会话始终允许，请按当前授权模式继续。”其他明确提出的任务限制仍需遵守，MCP 工具不能自行改变审批模式。

命令通过已认证 SSH ControlMaster 的独立非交互通道执行，复用 SSH 跳板和代理；失败不会另建连接，不使用 Codex 代理，也不共享终端当前目录、临时环境变量或 tmux 状态。

在 **Codex 接入 → SSH 会话接入 → 启动 Codex 标签** 的会话选择页，设置单条命令长度（256–32768 UTF-8 字节）、执行超时（1–3600 秒）、输出容量（1–8 MiB）以及默认审批模式（每条确认／本会话始终允许）。初始默认值仍为 4096 字节、60 秒、1 MiB、每条确认；有效设置自动保存，并包含在偏好备份中。接入首页不再重复显示执行设置；启动页表单可滚动，底部“取消”和“确认并启动”按钮固定可见。默认配置仅影响新标签。当前标签通过“执行设置”修改，点击“应用并继续授权”取消当前命令、重置额度并应用；普通“继续授权”沿用该标签的配置和审批模式。增大输出容量会增加内存和模型上下文消耗。

恢复之前的排查对话：先重新打开 SSH，在启动页选择当前 SSH 并勾选“恢复已有 Codex 对话”，确认后在 Codex 原生历史列表中选择旧对话。MyTerm 继续使用配置的代理；恢复的是 Codex 对话，不是旧 SSH 连接。即使重启 MyTerm 后 SSH UUID 改变，也会生成新的关联，`list_sessions` 返回当前 UUID、接入说明和授权状态；旧 UUID 的请求会被拒绝并提示重新获取。旧授权、任务 ID 和未完成命令不会作为本次有效任务复用。恢复后请核对目标，再给出继续任务的指示。旧对话中已出现的输出仍属于对话历史，“接入时读取已有输出”只控制本次 SSH 终端历史读取意图。对话列表与存储由 Codex 管理，MyTerm 不额外复制对话文件；首次恢复需使用支持 `codex resume --all` 的 CLI。参见 [Codex 官方恢复说明](https://learn.chatgpt.com/docs/developer-commands?surface=cli#codex-resume)。

执行控制栏铺满当前区域并使用统一背景：左侧为“SSH 执行”，中间为授权状态、续期与审批方式，右侧为执行设置；窄分屏仍可横向滚动。


执行栏的继续授权、审批模式和设置入口位于同一行，窄窗口或分屏可横向滚动；移除展开执行记录和常驻停止按钮，运行或排队时显示“取消当前命令”。关闭 Codex 标签结束对应授权；取消独立通道不保证终止远端已脱离会话的后台进程。输出不完整仍会阻止后续命令，`incomplete_reason` 区分 `output_limit`、`timeout`、`cancelled`、`output_read_error`；请先解释缺失内容，再调整范围或限制并继续授权，不应忽略不完整标记。

支持多行 shell 脚本（LF 换行与 Tab 缩进），一次提交默认最多 4096 UTF-8 字节（可配置）；整段脚本原样展示、审批并执行，计为一次命令额度。逐条审批时批准的是整段脚本，不是逐行确认。NUL、ESC、CR 等其他控制字符仍拒绝，Windows CRLF 文本请先转换为 LF。使用远端登录 shell 支持的语法，或显式调用所需解释器。

单条命令默认最多 60 秒，默认最多保留 1 MiB 输出，两项均可配置；实际超时还受剩余授权时间限制。通过 `command_status` 按 `next_offset` 读取全部输出；不能跳页，未读完不能请求下一命令。`all_output_delivered=true` 表示保留内容已全部返回，不保证模型仍保留全部上下文。超时、取消或容量超限会标记 `incomplete`，必须停止推进并说明，需要重新授权并缩小查询范围。取消会关闭执行通道，远端已脱离会话的后台进程可能继续运行；执行记录最多 50 条，只在内存保存。

### 命令状态

| 状态 | 含义与操作 |
| --- | --- |
| `awaiting_approval` | 尚未批准，在提交命令的 Codex 标签中确认或拒绝。 |
| `queued` | 已批准，等待同一 SSH 上的执行通道；轮询原 `job_id`，不要重复提交。 |
| `running` | 正在执行，按偏移读取输出；需要停止时取消当前任务。 |
| `completed` | 命令结束；读取全部分页，并检查退出码与 `incomplete`。 |
| `rejected` / `cancelled` / `failed` | 命令未执行、已取消或启动失败，检查原因后再决定下一步。 |

切回逐条确认不会撤销已批准的排队任务；要取消它，使用当前标签的“取消当前命令”。每个客户端只需读完自己上一条命令的输出，不等待其他客户端消费结果。授权到期后，排队任务会被拒绝，需在原标签续期后重新提交。

## 精简工具记录

默认精简执行工具返回内容：省略重复的命令、原因和授权说明，保留完整命令输出、当前审批模式、限制、错误及分页信息。需要详细元数据时，可告诉 Codex“使用 verbose=true 查看命令详情”；通过 `command_status` 查看已有任务即可，不要重新执行命令。此参数仅影响当前调用的返回内容，不修改审批权限，也不能隐藏 Codex 自己显示的工具名称和调用参数。

`command_status` 在运行中或排队中的任务没有新输出时，单次调用最多等待 20 秒；出现输出、状态变化或错误即返回。等待发生在 MCP 辅助进程，不阻塞应用审批和取消。Codex 仍会显示真实的工具调用，但不必频繁进行空轮询。

命令输出每页最多 16 KiB（UTF-8 字符边界可能使页面略短），减少大输出的分页调用次数，仍必须读完全部页面。

## MCP 工具与审批层次

| 工具 | 用途 |
| --- | --- |
| `list_sessions` | 内置客户端仅显示当前关联 SSH；外部客户端列出已共享 SSH，最多 32 项 |
| `read_output` | 读取历史、屏幕或选区，默认 200 行，最多 1000 行 / 8192 字节 |
| `capture_history` / `read_history_page` | 冻结较大历史范围并完整分页读取 |
| `execute_command` | 按 MyTerm 当前授权和审批模式提交命令 |
| `command_status` | 查询状态、退出码及分页输出 |
| `cancel_command` | 拒绝或停止待执行/执行中的命令 |

MyTerm 为内置 SSH 分析标签配置上述 MCP 工具的免重复工具审批，并使用 Codex 本地只读沙箱。**MCP 调用免重复审批不等于 SSH 命令免审批**：SSH 授权与命令审批由 MyTerm 独立强制执行。不修改全局命令审批规则，也不使用 `printf` 管道回退。外部 IDE 的工具审批配置独立管理。

终端输出视为不可信数据，不能当作执行授权。接口不提供凭据读取或任意终端按键注入；执行命令本身仍可能修改远端文件，须按授权范围使用。

旧客户端调用 `propose_plan` 时仅收到“不再需要记录计划”的兼容响应，不存储计划、不创建执行记录，也不授予执行权限。新客户端不再列出该工具。

## 独立代理

Codex 配置保存在 `codex.connection`，仅向新建 Codex 进程传入代理环境，不修改 SSH 配置、系统代理、MyTerm 主进程环境或 `~/.ssh/config`。

HTTP 代理直接用于 Codex；SOCKS5 经本地 HTTP CONNECT → SOCKS5 转换通道，监听 `127.0.0.1` 随机端口，使用随机代理认证，由 SOCKS5 服务端解析目标域名，无直连重试。每个标签各自持有通道；代理认证信息保存在独立 `MyTerm/CodexCredentials` 加密存储，不进入 SSH 密码库或系统钥匙串，也不包含在偏好备份中。

外部 Codex/IDE 和登录浏览器的代理需各自配置，不继承 MyTerm 内置标签的代理设置。

## 外部 MCP 与进程生命周期

“配置外部 Codex 的 MyTerm MCP”注册当前 MyTerm 可执行文件及 `--myterm-mcp` 参数。界面会回读注册状态、路径和检查时间；注册成功不等于外部 IDE 已重新加载。应用移动后需重新注册，建议安装到 `/Applications/MyTerm.app` 后操作。内置 Codex 标签不需要手工注册外部 MCP。

MCP 通过标准输入输出与 Codex 通信，再经带认证的同用户 Unix socket 访问 MyTerm。描述文件权限为 0600；关闭共享撤销发现信息、授权与缓存。

外部 Codex/IDE 持有的适配器可能在 MyTerm 退出后继续等待请求，通信管道关闭后退出。此时不能读取已退出应用的会话；MyTerm 重开并重新授权后，可读取新的桥接配置。安装脚本区分 GUI 与 MCP 适配器，不误杀外部适配器。工具定义变化后需重新启动外部 Codex/IDE 以加载新版适配器。

MyTerm 内置 Codex 标签随应用退出会走标签终止流程，正常情况下其 MCP 管道也应关闭。若进程长期残留，应检查父子进程和管道，而不能仅凭名称判断为正常外部进程或内存泄漏；安装脚本的分类不保证清理所有异常子进程。

## 检查入口

- `scripts/check.sh`：协议、代理配置隔离、快照及执行规则。
- `scripts/window-controls-check.py <MyTerm.app>`：stdio MCP、私有 socket、授权撤销、分页、界面、启动及退出诊断。
- `scripts/codex-execution-check.py`：临时本地 SSH 的真实连接复用、输出、退出码和父连接保留，发布流程包含此检查。
- `scripts/codex-proxy-check.py`：本机 Codex CLI 的 HTTP / SOCKS5 代理及认证测试；先构建 Debug 的 `MyTermChecks` 和 `MyTermProxy`，不使用真实模型密钥。

实现依据：[CodexConnection.swift](../Sources/MyTermCore/CodexConnection.swift)、[CodexMCP.swift](../Sources/MyTermCore/CodexMCP.swift)、[CodexBridge.swift](../Sources/MyTerm/CodexBridge.swift)。
