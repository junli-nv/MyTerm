## 产品目标与范围

- macOS 原生终端工作台，起点是类似 MobaXterm 的 SSH 使用体验。使用 SwiftUI/AppKit、SwiftTerm、系统 OpenSSH，兼顾本地 Bash、SSH、文件传输和 Codex。
- 优先把 macOS 终端体验做好。Windows 版和 VNC 曾讨论，均未列入当前实施范围；通用多 AI 工具接入也暂缓，当前继续支持 Codex。
- 面向用户而非要求用户编译：README 前面放 DMG 安装、依赖、首次权限及基本使用，源码构建与测试放后面。当前文档中英文同步维护。
- 作者署名为 Junli Zhang，链接到公开 GitHub 主页，不展示邮箱。仓库为 https://github.com/junli-nv/MyTerm。
- 可维护性优先：分离界面、状态、协议和进程管理，避免把修复堆进一个大型回调；为行为边界做有意义的回归验证。

## 关键设计与演进

### SSH、凭据与跳板机

SSH 支持密码/密钥、OpenSSH 导入导出、跳板链、独立 HTTP/SOCKS5 代理、端口转发、压缩、保活和调试。X11 默认关闭。新建 SSH 时可填写密码，也可留空后续询问；密码与密钥认证选择应清晰。编辑无关配置不应清除仍有效的密码或密钥关联。旧密码被拒绝后用户更新的密码应供后续连接复用。

凭据由应用维护，不以系统钥匙串为默认存储方案。密码支持命名、查看及关联会话；密钥支持关联查询和删除引用中密钥的额外确认。偏好备份可以包含敏感信息，必须保留加密和校验。OpenSSH 导出不应导出密码。

跳板机发展为独立管理的共享定义，支持命名、增删改查、引用关系及路径测试；已有配置需迁移，复用同一路径/用户凭据，避免反复输入。不同凭据、代理或跳转路径不能只因 IP 相同就合并。删除引用中的跳板须先解除引用。测试必须兼容 Windows 和仅允许转发的跳板，不能把不支持远端 Unix 命令误判为 SSH 不可用。OpenSSH 导出需要正确区分重复地址、别名与实际引用。

SSH 编辑器已移除整套“选择已有跳板配置”入口；通过“选择已有跳板机”逐级添加或“更换跳板机”替换某一级，保留独立跳板机管理。选择单个跳板不替换其他路径或代理，已有引用与凭据继续保留。

### 标签、布局、输入与主题

- 默认打开开始页，不自动新建本地 Shell。保存的 SSH 配置双击连接；标签单击选中后即可右键操作，不能要求第二次点击来获取焦点。
- 标签可拖动排序；“编辑标签”统一名称、颜色和环境标识。保存会话支持树形分组、拖入/移出以及未分组会话之间拖放建组。
- 保留双击标签栏空白处最大化/还原。压缩标题区域，底栏可隐藏；SSH 的 SFTP 入口放在右上角，切换本地与 SSH 时避免布局抖动。
- 支持上下/左右分屏与可配置快捷键，默认 `⌘⇧H` / `⌘⇧V`。拆分当前区域为两半，其他比例保持；本地/SSH 拆分默认新建同类型连接。广播命令只发给用户明确选择的区域。
- 选中复制、右键粘贴是重要使用习惯。兼容 tmux/vim、中文输入法、长按重复键、软折行复制、持续输出时选择文本。不要用全局拦截破坏全屏程序的输入或鼠标协议。
- 字体下限降到 5 pt，支持 Ctrl+双指缩放和 `⌘+`/`⌘-`，步进小；主题支持色板、ANSI 颜色和透明度。移除自定义字体名称输入和字体搜索控件，保留字体选择。
- 设置与 Codex 接入使用纵向分类；小窗口能滚动，确认/取消可见。语言切换立即生效，包括系统插入的菜单项。配置窗口跟随当前桌面。

### 文件传输

以 SFTP 为文件管理入口，独立 SCP 界面已移除。支持明确断开、可靠选择、多选、右键下载、拖拽上传下载、目录递归、速度、续传与独立面板窗口。右上角入口不应依赖底栏展开。

同名文件应让用户决定覆盖/跳过及批量策略；不能因冲突断开 SFTP，也不能静默生成 `.0` 等名称。覆盖与续传是不同选择，必须保留中断重试能力。ZMODEM 的冲突、暂存和续传策略与 SFTP 不完全相同，不能宣称具有相同的源文件校验。

MyTerm 内置 trzsz 客户端，远端需要 `trz`/`tsz`；ZMODEM 需要本机和远端 `rz`/`sz`。tmux 使用 trzsz，注意跳板中继。传输探测不能吞掉正常输入回显，如单个 `*`，也不能因降低等待而破坏协议识别。

### 历史、日志与资源生命周期

内存回看与磁盘日志分开。默认不保存磁盘日志；全局默认可由单会话覆盖，支持行数、容量、清理、导出和压缩。历史搜索服务于现有缓冲，不可声称找回已淘汰内容。

曾发现退出画面保留时 PTY 释放延迟、历史模块 UUID 集合清理缺口，以及大量终端缓冲行占用内存。已围绕这些问题修复并加入全局历史内存估算预算：默认 256 MiB，均分给终端标签，0 表示仅行数限制。它不是进程总内存硬上限；屏幕、图片、UI 等不计入。不能由一次稳定采样推断长期零泄漏。

正常退出的本地/SSH 标签按退出行为关闭；网络断线保留输出、显示状态，允许 R/r 重连。外部 Codex/IDE 的 `MyTerm --myterm-mcp` 进程不等同于 GUI 残留，必须核对父进程与管道，不可按名字全部杀掉。

### Codex 的边界与授权

详细契约见 [Codex 接入](CODEX-INTEGRATION.md)。以下是最易被旧对话误导的决定：

| 早期方案 | 后续决定与当前约束 |
| --- | --- |
| 只读 SSH 接入 | 支持执行；启动页默认勾选允许执行，确认关联才生效，仍可取消勾选保持只读 |
| 固定逐条确认 | 支持单次允许及本会话始终允许，可随时切换；应用实际模式不能被旧提示词覆盖 |
| 固定 10 分钟/30 条授权 | 授权时长与额度可配置，运行标签可续期；不要写死旧值 |
| 固定 4096 字节/60 秒/1 MiB | 这些仍是初始默认值，但限制与默认审批模式可配置，支持多行脚本 |
| MyTerm 捕获并确认计划 | 计划由 Codex 输出，不再在 MyTerm 重复展示；命令审批独立保留 |
| 持续监控 SSH 输出 | 已移除后台自动循环采样；不影响给定任务后的多步执行与结果读取 |
| 接入先读取旧历史 | 默认从后续任务开始，读取已有输出由启动选项决定；这不是历史权限隔离 |
| 本地 Codex 必须关联 Bash | 直接在指定工作目录启动本地 Codex，复用代理，不需要关联 Bash，也不启用 MyTerm MCP |
| 全局 SSH 共享开关和复制会话 ID | 选择 SSH 后建立关联，内置标签自动接收 ID；不要求手工复制，也不再保留多余全局撤销入口 |
| 一个 SSH 只有一份执行授权 | 多个 Codex 标签各自管理授权、额度和读取进度，同一 SSH 执行通道串行排队 |
| 强制 `--no-alt-screen` / 接管 Codex 滚动 | 已撤回；保留终端协议路由，避免重复施加过时显示设置 |

Codex 代理和 SSH 代理完全独立。登录状态应复用，不因重开标签重复登录；路径、代理、登录、外部 MCP 注册和 SSH MCP 健康检查分别反馈状态。MCP、macOS 系统权限和命令审批是不同层次。

通过已认证 SSH ControlMaster 的独立非交互通道执行命令，不共享交互终端的当前目录、临时环境或 tmux 状态。必须取完输出分页并检查完整性；`incomplete` 必须解释原因，不可以为减少提示而静默忽略。`execute_command`/`command_status` 默认精简，状态等待减少无数据轮询；Codex 的工具调用 UI 不由 MyTerm 控制。

Codex 对话按用户选择的集群/项目组织，有默认项目；支持命名、继续历史对话并重新关联新的 SSH UUID。索引可删除、未来项目存储目录可配置，但不把 MyTerm 索引等同于 Codex 自身历史。关闭一个 Codex 标签只结束它的授权，不应破坏同一 SSH 上其他标签。

## 诊断与尚未解决的问题

1. **Codex 滚动跳转仍有已知问题。** 持续输出时上翻可能跳到较早历史；曾尝试强制接管滚动但反馈更严重，已撤回。不能将后来发布等同于修复成功。需要记录缓冲模式、鼠标报告、滚动和输出时序再定位。
2. **少量 SwiftUI 菜单泄漏没有充分证据证明已消除。** 先前现场扫描出现小规模泄漏，不能与较大的历史缓冲占用混为一谈；后续需隔离实例、重复开关和采样验证，避免结束用户工作。
3. **SSH MCP 检查不是 Codex 全链路检查。** 当前检查直接启动 MyTerm MCP，验证初始化及工具发现，不启动 Codex 自身的 Code Mode host。用户反馈某次故障来自 Codex 辅助程序被系统拦截；不能把所有 handshake 失败归结为此。
4. **权限不能一键永久预授权。** Codex 辅助程序可能独立触发提示，安装/升级后应做实际 SSH 接入测试；Gatekeeper 评估失败本身不是故障根因。详见 [权限说明](PERMISSIONS.md)。
5. **不宣称测试覆盖所有环境。** 真实远端、系统输入法、触摸板、第三方 TUI 升级、企业策略等仍可能需要用户环境复现。测试报告必须区分通过、未测、无法复现和已知失败。

“帮助 → 终端诊断”提供有界、主动开启的记录与中英文可读摘要。保留时间、阶段、错误类别和建议，不记录终端正文或凭据；固定规则解释，不调用模型。诊断不足时应说明缺失证据，不能把正常 EOF、进程名或一个退出码直接当成根因。

## 开发、安装与发布约定

以 [AGENTS.md](../AGENTS.md) 为操作规范。修改前检查用户工作区；不要回滚无关修改。使用 Bash；Python 环境遵循当前机器约定，不把原维护者个人路径复制成其他贡献者的必要条件。

功能变更须验证代码、文档、Debug/Release 以及实际 DMG 拷贝的行为；运行相关回归，记录无法验证的场景。配置与菜单需检查中英文、最小尺寸、状态变化及首次加载。开发版能运行不等于安装版可用。应用修改按规范更新安装包并用安装脚本验证；仅文档变更不需要构建或重启。

原维护者已授权 DMG 检查通过后安装，且曾明确暂停替换工作中的实例；接手时尊重当前用户最新约束，不把原机器上的授权扩展到其他人的机器。提交、推送、发布和删除旧 Release 是不同操作，应报告完成到哪一步。只在请求发布时发布；历史清理要求曾多次变化，不能把某次“只保留最新”当成永久清理政策。保留源码标签与历史 changelog，未明确要求时保留已有 Release。

补丁版本到 `.12` 后递增次版本。版本历经 1.x、2.0、3.0、3.1、3.2（分屏）、3.3 及 3.4；历史明细查 changelog，不靠本摘要重建发布说明。

## 如何持续维护

当产品范围、核心行为、授权模型、发布流程或已知问题状态改变时，同步更新本文件与英文版；给已解决问题写明证据，不只删掉问题描述。临时排查数据留在诊断报告，不把日志和敏感信息复制进来。交接快照更新时标日期，并重新检查 Git/版本；不要静默把旧快照写成实时状态。具体用法维护在 README/专题文档，逐版事实维护在 CHANGELOG，操作规则维护在 AGENTS，本文记录跨会话容易遗失的理由与约束。
